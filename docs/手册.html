为什么需要这个工具

通过了 KYC（身份验证）并不意味着你的 Claude 账号就能高枕无忧。Claude 会持续根据你的出口 IP、本机行为等信号进行风控检测——如果你的 IP 频繁变动、前后不一致，即使账号本身没有违规，也可能触发封禁。

关键建议：所有 Claude 流量都应走一个干净的、固定的家庭 ISP 宽带 IP。机房 IP、共享 IP、数据中心 IP 这类"不干净"的出口，本身就是风控的高危信号。一旦环境不干净，再怎么固定也挡不住封号。固定一个干净的家庭宽带 IP，才是最根本的防护。

Claude Network Lock 就是配合这个思路的工具：它像一个"门卫"，每次启动前先确认网络出口和上次一样，才放 Claude Code 通行；启动之后，也只允许它走你指定的那一条路上网。出口一旦不对，它宁可不启动，也不会让 Claude Code 换条路偷偷连网。

第一章

它能帮你做什么

很多人上网时，公网 IP（也就是别人看到你"从哪里来"的地址）并不是固定的：网络重连、代理工具自动切换、运营商重新分配地址，都可能让它悄悄变掉。对于需要长时间稳定连接的在线服务来说，出口忽东忽西，看起来就不太正常。

本工具解决的就是这个问题，它会：

  • 每次启动前，确认 Claude Code 是官方原版、没有被替换；
  • 确认网络出口和你安装时记录的一致，不一致就拒绝启动；
  • 启动后，把 Claude Code 及其打开的所有程序"关"在一个只能走指定端口的环境里，防止它绕路直连；
  • 不让 Claude Code 自动打开浏览器，避免浏览器走了别的网络。

它不会修改 Claude Code 本身，用到的全是 macOS 自带的工具。

第二章

它是怎么工作的

可以把它想成三道关：

第一关：启动前检查
身份、端口、出口都没问题
第二关：Claude Code 在"隔离环境"中运行
只能连本机指定端口
第三关：你自己的代理工具
固定出口，失效时直接断开
固定的公网出口
图 1 三道关示意

第一关：启动前检查。每次运行 claude-locked，它都会依次确认：

  1. Claude Code 文件没被改过，签名是官方的；
  2. 你指定的本地代理端口正在工作；
  3. 用两个不同的网站查询出口 IP，结果一致；
  4. 这个 IP 和安装时记录的一样（配置里只存 IP 的"指纹"，不存 IP 本身）。

任何一项不通过，就直接停下并告诉你原因。

第二关：隔离运行。借助 macOS 自带的沙盒功能，Claude Code 启动后只能连接本机的那一个代理端口，连它运行的命令、脚本也一样受限。想直接连外网？连不上。

第三关：你的代理工具。这一关由你自己的代理工具负责：那个专用端口要始终对应同一个出口，出问题时直接断开，而不是自动换一个。

第三章

安装前的准备

需要什么说明
一台 Mac系统需带有 sandbox-exec（目前的 macOS 都有）
官方 Claude Code已经安装好，能正常使用
你自己的代理工具任意一款即可，需支持 HTTP 端口，并符合所在地法律法规
一个固定的出口稳定、合规、由你自己控制

你的代理工具需要准备一个专门给 Claude Code 用的端口（下文以 7899 为例），并满足四点：

  1. 只在本机监听（127.0.0.1），不对局域网开放；
  2. 始终走同一个出口，不跟着你平时的切换而变化；
  3. 没有"自动选择""失败后改走其他线路""直连"之类的设置；
  4. 出口不可用时直接连不上，而不是换一条路。

具体怎么设置，请参考你所用工具的官方说明，本手册不针对任何特定软件。

准备好后，在终端里运行下面两条命令，两次显示的 IP 应该完全一样：

curl --proxy http://127.0.0.1:7899 https://api.ipify.org
curl --proxy http://127.0.0.1:7899 https://ifconfig.me/ip
第四章

首次使用前：清理旧的本机痕迹

如果你之前已经用过 Claude Code，电脑上会留下登录凭据、会话记录、设备标识等本地数据。这些数据不会因为安装了网络锁就自动消失。为了让网络锁从一个干净的起点开始工作，建议在首次安装前做一次清理。

如果你是全新安装 Claude Code、从未使用过，可以跳过本章。

哪些东西需要清理

Claude Code 在本机存放的数据主要包括：

  • 登录凭据：macOS 钥匙串里的 Claude Code-credentials，以及 ~/.claude.json 中的 OAuth 账号信息；
  • 设备标识：~/.claude.json 中的 machineID、userID、anonymousId 等字段——其中 userID 会作为遥测的设备 ID 上报；
  • 会话历史：~/.claude/projects/（包含每个项目的对话记录，带有 session ID 和账号标识）、~/.claude/history.jsonl、~/.claude/file-history/；
  • 遥测数据：~/.claude/telemetry/，每条事件都包含 session、设备和账号标识；
  • 内部备份：~/.claude/backups/ 中保存了多份旧 .claude.json，包含相同的身份字段；
  • 缓存和运行态：~/.claude/cache/、~/Library/Caches/claude-cli-nodejs/ 等。

只轮换一个 machineID 是不够的——上面这些地方都携带关联信息。

清理步骤

清理前请先退出所有 Claude Code 进程。

1

备份——把现有数据完整复制一份，以防万一

backup_dir=~/claude-cleanup-backup/$(date +%Y%m%d-%H%M%S)
mkdir -p "$backup_dir"
cp -a ~/.claude "$backup_dir/dot-claude"
cp -p ~/.claude.json "$backup_dir/dot-claude.json" 2>/dev/null
chmod -R 700 "$backup_dir"
2

保留你需要的配置——把设置和插件单独拷出来

keep_dir="$backup_dir/keep"
mkdir -p "$keep_dir/plugins"
cp -p ~/.claude/settings.json "$keep_dir/" 2>/dev/null
cp -p ~/.claude/settings.local.json "$keep_dir/" 2>/dev/null
cp -a ~/.claude/skills "$keep_dir/skills" 2>/dev/null
for f in config.json installed_plugins.json known_marketplaces.json blocklist.json; do
  cp -p ~/.claude/plugins/$f "$keep_dir/plugins/" 2>/dev/null
done
3

删除旧身份和历史

# 移除旧的身份文件
rm -f ~/.claude.json

# 移除会话历史、遥测、缓存和内部备份
rm -rf ~/.claude/projects ~/.claude/history.jsonl ~/.claude/file-history
rm -rf ~/.claude/telemetry ~/.claude/cache ~/.claude/stats-cache.json
rm -rf ~/.claude/backups ~/.claude/daemon.log
rm -rf ~/.claude/jobs ~/.claude/sessions ~/.claude/session-env
rm -rf ~/Library/Caches/claude-cli-nodejs
4

删除钥匙串里的旧登录

security delete-generic-password -s "Claude Code-credentials" 2>/dev/null
5

把保留的配置放回去

cp -p "$keep_dir/settings.json" ~/.claude/ 2>/dev/null
cp -p "$keep_dir/settings.local.json" ~/.claude/ 2>/dev/null
cp -a "$keep_dir/skills" ~/.claude/skills 2>/dev/null
mkdir -p ~/.claude/plugins
for f in config.json installed_plugins.json known_marketplaces.json blocklist.json; do
  cp -p "$keep_dir/plugins/$f" ~/.claude/plugins/ 2>/dev/null
done
清理范围说明
本章只处理 Claude Code CLI 的本地数据。Claude Desktop（桌面版）、项目里的 .claude/ 目录、以及服务端已有的记录，均不受影响。清理本地痕迹不能删除 Anthropic 服务端的数据，也不能保证账号不被风控。

清理完成后，下次启动 Claude Code 时它会重新生成本地身份文件，届时再用网络锁登录即可。

第五章

三步完成安装

1

下载本项目，在终端进入项目文件夹，运行安装器

chmod +x scripts/install.zsh
./scripts/install.zsh --proxy-port 7899

安装器会显示检测到的出口（部分打码）并询问是否确认，输入 y 回车即可。

2

让终端能找到新命令（只需做一次）

echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
3

运行自检

claude-locked --lock-self-test

看到"自检通过"就说明一切正常。自检会实际尝试直连外网、打开浏览器等操作，确认它们都被拦住了。

第六章

日常使用

启动：先打开你的代理工具，然后把平时输入的 claude 换成：

claude-locked

登录账号：运行 claude-locked auth login。因为工具不允许自动打开浏览器，请手动复制终端里显示的链接，在同样走这个固定出口的浏览器里打开。浏览器不受本工具管控，需要你自己确认。

Claude Code 更新之后：文件变了，工具会按设计拒绝启动。确认更新来自官方后，重新运行一次安装器和自检即可：

./scripts/install.zsh --proxy-port 7899
claude-locked --lock-self-test

需要访问本机开发服务（例如 3000 端口）：在 ~/.config/claude-network-lock/local-ports 里每行写一个端口号，改完重新自检。

注意
不要把任何代理或转发服务的端口加进这个列表，否则 Claude Code 就可能借它绕过固定出口。

卸载：

./scripts/uninstall.zsh                  # 只删除启动命令，保留配置
./scripts/uninstall.zsh --purge-config   # 连配置一起删除
第七章

遇到问题怎么办

提示信息原因怎么办
缺少配置还没安装，或配置被删了运行安装器
端口未监听代理工具没开，或端口没设好打开代理工具，确认专用端口已启用
出口验证失败代理连不上外网，或查询网站暂时不可用检查代理工具能否正常上网，稍后重试
两个出口查询结果不一致端口没有固定在一个出口上检查代理工具里是否开了自动切换
出口与安装时不符出口 IP 变了先查原因；确认新出口没问题后重新安装
Claude 文件已变化Claude Code 更新了确认来自官方后重新安装
配置不能由 group/other 写入配置文件权限太宽运行 chmod 600 ~/.config/claude-network-lock/config
第八章

常见问题

会改动 Claude Code 吗？
不会。它只是在外面"套了一层"再启动 Claude Code，不碰 Claude Code 的任何文件。
每次启动会不会很慢？
通常只多 1～3 秒，主要花在两次出口查询上。
MCP、插件等功能还能用吗？
需要联网的会经由同一个代理端口出去；需要连接本机其他端口的，按第六章加入白名单即可。
运行过程中出口变了，它能发现吗？
不能。检查只在启动时做，所以第三关（你的代理工具不自动切换）很重要。
和 Anthropic 官方有关系吗？
没有。这是独立的开源项目，与 Anthropic 无隶属或背书关系。
第九章

它做不到的事与免责声明

这个工具只管"本机上的 Claude Code 怎么上网"，以下事情它管不了：

  • 不能保证账号不会触发平台风控，也不能改变平台已有的记录；
  • 不能把会变动、多人共用的出口变成稳定独享的出口；
  • 管不到浏览器、桌面版 Claude、IDE 插件等其他入口；
  • 防不住电脑上已经存在的恶意程序；
  • 如果将来 macOS 移除了 sandbox-exec，隔离功能将无法使用。
